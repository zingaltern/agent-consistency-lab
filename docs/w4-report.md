# W4 实验报告：上下文工程（视图 / 卸载 / 压缩 / 缓存纪律 / 预算）

**日期**：2026-09-16 ｜ **代码**：`harness/context.py`、`cache.py`、`compaction.py`、`artifacts.py`、
`budget.py`、`llm.py` ｜ **数据**：`reports/w4_context_cost.json`、`reports/w4_crash_matrix.json`

> **边界（先说）**：本轮所有成本数字都来自本项目的**缓存模型**（前缀匹配 + 5 分钟 TTL +
> 1.25× 写溢价 + 0.1× 读折扣，最小可缓存 1024 token）与**脚本模型**（确定性、无网络），
> 不是真实 API 的实测；token 量用项目内的确定性估算器。结论是"在同一模型下的相对比较"，
> 绝对金额与真实账单不可直接对照。真实接入时替换 tokenizer / 价格表 / 缓存参数即可复用全部实验代码。
>
> **脚本模型测不了质量**：模型输出是确定性脚本，本轮只能测成本、缓存与一致性，
> 不能对"回答好不好"做任何断言（质量维度要等 W5 接真实模型 + W6 接评测台）。
>
> **复算参数**（`experiments/context_cost.py` 的常量）：窗口 10000 token、最大输出 1024、
> 内联上限 100000（=不卸载）、场景 `long_incident`（8 轮取证日志 × 60 行）。
> 跨进程缓存不在本模型内（每个 worker 进程新建缓存），因此审批/恢复后的首调用结构性冷 miss；
> 真实供应商的前缀缓存在服务端跨进程持久，这会系统性压低本报告的命中率。

## 一、模型的三个承诺（都可测）

| 承诺 | 落点 | 断言方式 |
|---|---|---|
| 视图结构合法：工具调用与结果配对、批次原子、观测唯一 | `context.py` 的三条不变式 | 违规批次整体丢弃并记录 `View.violations`（测试 4 例） |
| 卸载确定性：同一结果两次渲染逐字相同 | 内容寻址 artifact（sha256） | `test_large_tool_result_is_offloaded_deterministically` |
| 压缩原子：要么完整生效要么完全没发生 | 先写 artifact、再追加事件 | 窗口 5 崩溃矩阵 + artifact 引用完整性断言 |

## 二、成本实验（同一条长任务：8 轮取证 + 1 次高危写 + 终答，共 10 次模型调用）

| 配置 | 状态 | 调用数 | token/调用 | 命中率 | 主桶成本/调用 | 压缩桶成本/调用 | 压缩次数 | 溢出 | 视图违规 |
|---|---|---|---|---|---|---|---|---|---|
| E1a-纪律-动态在尾部 | completed | 10 | 1494 | 57.4% | $0.00293 | $0.00000 | 0 | 0 | 0 |
| E1b-反面-动态进前缀 | completed | 10 | 1482 | 0.0% | $0.00602 | $0.00000 | 0 | 0 | 0 |
| E2a-大结果内联-小窗口-无压缩 | failed | 5 | 4355 | 59.3% | $0.00756 | $0.00000 | 0 | 1 | 0 |
| E2b-大结果内联-小窗口-有压缩 | completed | 10 | 4421 | 35.0% | $0.01078 | $0.00357 | 3 | 0 | 0 |
| E2c-结果卸载-小窗口-无压缩 | completed | 10 | 1494 | 57.4% | $0.00293 | $0.00000 | 0 | 0 | 0 |

### 结论（数字由 `reports/w4_context_cost.json` 直接生成，可复算）

1. **缓存纪律值 2 倍成本**：运行时信息进前缀后命中率 57.4% →
   0.0%，成本/调用 $0.00293 → $0.00602
   （**+105.1%**）。原因不只是少读缓存，更在于每个块都要按 1.25× 写溢价
   重新写入（缓存写 token 2028 → 12678）。
2. **卸载是本次唯一"纯赚"的杠杆**：小窗口下不卸载跑不完（第 6 次调用尝试溢出、
   任务 `failed`，前 5 次成功）；卸载后 token/调用 1494、
   成本/调用 $0.00293，且完全不依赖模型调用。
   ⚠️ 口径：不卸载那次是**截断期均值**（只跑完 5 次），不能与完整运行比绝对值。
3. **压缩是拿钱买可用性**：开压缩后任务跑完（3 次压缩、0 次溢出），
   但账本口径成本/调用 $0.01436（主桶 $0.01078 +
   压缩桶 $0.00357），命中率 35.0%；
   与卸载路径相比是 **4.9 倍**——每次压缩都从替换点击穿前缀缓存，
   摘要调用自身也要花钱。
4. 触发策略应当是**"先卸载、后压缩"**；**"阈值尽量高"目前是外推而非实测**（本轮只做
   "触发 vs 不触发"，没有阈值扫描；W7 补三维曲线）。
5. **压缩触发退化已修**：早期固定 13k 余量在窗口 10k 时使 `should_compact` 恒真
   （退化为每步压缩，一轮 7 次）；现在余量按 `min(buffer, usable×25%)` 钳位，同任务降到
   3 次——这解释了本报告与早期数字的差异。
6. **视图健康度**：所有配置 `view_violations` = 0。审计发现审批路径曾固定产生 2 条违规
   （已批准写操作的调用与结果被整段丢出模型视图），修复后由矩阵与成本实验持续断言。

## 六、独立审计与修复（W4.5）

W1–W4 之后跑了一次**五路独立审计**（只读代理，各自负责一个维度：文档一致性、测试有效性
（含变异测试）、实验可复现性、状态机正确性、工程卫生）。审计发现的 P0 全部已修并固化成
回归用例（`tests/test_audit_regressions.py`）：

| # | 缺陷（审计实测复现） | 修复 |
|---|---|---|
| P0-1 | **视图在审批路径自毁配对**：`interrupt`/`resume` 触发批次收束，导致"提议写 → 人审批 → 执行"的调用与结果被整段丢弃（`view_violations=2` 是常态，模型看不到自己写了什么） | 批次只在 turn 边界收束；`evaluate()`/`collect()` 现在断言视图违规必须为 0 |
| P0-2 | **分叉跨分支复用幂等键**：子分支上同一 `tool_call_id` 命中父分支的去重行，静默复用**另一组参数**的结果并**跳过审批门**（幻影写） | 幂等键纳入 `branch_id`；去重命中时校验 `args_sha256`，不一致即拒绝；新增分叉回归测试 |
| P0-3 | **工具异常穿透 loop**：异常直接冒泡，run 永久 `RUNNING`、调用悬挂、每次 resume 重放同一副作用 | 异常分类落地：非幂等写 → `unknown` 等对账，只读/幂等 → `failed`；未知工具名同样分类；探针异常视为不确定 |
| P0-4 | **压缩可能越压越大**：摘要长于被替换内容时仍写入，`should_compact` 恒真 → 每步重压直至 overflow | 无收益即中止（记 `compaction_no_gain`）；余量按 `min(buffer, usable×25%)` 钳位，消除"每步压缩"退化 |
| P1 | 终态不是吸收态（fatal 后可被 interrupt 复活并真的执行副作用）、预算 `per_bucket` 覆盖总量上限、compaction 桶不硬停、`_find_approval` 被更晚的 session 拒绝否决精确批准 | 全部修复并加测试；恢复时新增 checkpoint 交叉校验（`checkpoint_log_mismatch`） |
| 文档 | "恢复 = checkpoint + 重放 writes" 与实际恢复路径（事件日志 + outbox/探针）背离；`lease`/`state_update` 被写成已落地；W3 "70 次 SIGKILL" 实为 65 次 | 逐条更正（见 `docs/semantics.md` §1/§2.4/§3/§4） |

审计同时确认了实验的可复现性：崩溃矩阵重跑 3 轮、成本实验重跑 2 轮，逐格/逐字段零差异；
矩阵 80 次运行全部 as-predicted，未发现 flaky。
